# Prospect Database

> Operator-run tracker for Phase 6 concierge sales. The CSV is generated by
> `npm run sales:seed-prospects` and **contains personal/company data — it is
> git-ignored and never committed**. This page documents the columns and the
> workflow; the actual rows live in `docs/sales/prospects.csv` (local only).

## Columns

| Column | Meaning |
| --- | --- |
| `id` | stable short id (`P01`) |
| `name` | prospect / company |
| `role` | e.g. "BD lead, payments infra" |
| `vertical` | payments / regtech / lending / consulting / VC |
| `source` | how found (referral, podcast, conference, LinkedIn) |
| `status` | `lead` / `contacted` / `discovery-call` / `deliverable-sent` / `paying` / `not-a-fit` |
| `last_contacted` | ISO date |
| `gate_evidence` | JSON pointer to recorded evidence (call notes, invoice, referral) |
| `notes` | free text |

## Workflow

1. `npm run sales:seed-prospects` — (re)creates the skeleton CSV (header + example rows).
2. Operator adds real prospects and updates status as the pipeline moves.
3. Discovery calls follow [CUSTOMER-DISCOVERY.md](./CUSTOMER-DISCOVERY.md).
4. Deliverables follow [RESEARCH-OUTPUT-TEMPLATE.md](./RESEARCH-OUTPUT-TEMPLATE.md).
5. Gate evidence is marked on the row **and** cross-checked against
   [VALIDATION-GATE.md](./VALIDATION-GATE.md) every 2 weeks.

## Privacy rules

- Real contact details stay local (git-ignored), never in the repo or in logs.
- Only status/aggregate evidence is ever discussed publicly.
- Export the CSV before sharing anything externally.
